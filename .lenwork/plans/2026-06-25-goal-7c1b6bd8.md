Here’s a concrete, safe plan to replace the current in-memory fixtures with a **local JSON “demo database”** that persists bets between runs when `DEMO_MODE=1`.

## Goal
In `DEMO_MODE=1`:
- Users, matches, bets are loaded from local JSON files
- “Save bets” actually **persists** by writing to the JSON
- Seed data includes **5 users** and **10 matches**, covering:
  - past games (some bet, some unbet)
  - future games (some bet, some unbet)
  - optionally one “LIVE” game

## What schema we’ll use (implied by current code)
From `app/data/fixtures.py` and `app/core/bets.py` expectations:

### users
```json
{"username": "alice", "pin": "1111"}
```

### matches
Keys used across UI:
- `match_id` (str), `match_number` (int), `utc_date` (ISO string)
- teams: `home_team`, `away_team`, `home_code`, `away_code`, `home_crest`, `away_crest`
- status-ish: `status` (e.g., SCHEDULED/LIVE/FINISHED)
- group/stage: `stage`, `group_name`
- scoring fields: `flt_home`, `flt_away`, `ext_home`, `ext_away`, `pens_home`, `pens_away`
- misc: `duration`, `minute`

### bets
```json
{
  "username": "alice",
  "match_id": "m1",
  "home_bet": 1,
  "away_bet": 0,
  "status": "pending|closed|...",
  "points": null|number,
  "updated_at": "ISO string"
}
```

## Implementation plan (step-by-step)

### Step 1 — Add demo JSON storage module
**Add:** `app/data/demo_store.py` (or similar)
- Responsible for:
  - locating files (e.g. `demo_db/users.json`, `demo_db/matches.json`, `demo_db/bets.json`)
  - `load_*()` and `save_*()` helpers
  - `init_demo_db_if_missing()` to seed files on first run

**Expected outcome:** a single place that defines file paths + read/write behavior.

### Step 2 — Create seeded JSON files (5 users, 10 matches, mixed bets)
**Add folder:** `demo_db/`
- `demo_db/users.json` → 5 users
- `demo_db/matches.json` → 10 matches:
  - e.g. 3 finished (past), 1 live/just started, 6 future
- `demo_db/bets.json` → pre-seeded bets:
  - some users have bets on past matches (closed)
  - some past matches have missing bets (unbet past)
  - some future matches have bets (pending)
  - some future matches have no bets (unbet future)

**Expected outcome:** you can log in as any of the 5 users and see realistic “already bet / not bet” behavior across tabs.

### Step 3 — Switch DEMO_MODE DAL reads to JSON instead of fixtures
Update these modules so that when `demo_mode_enabled()`:
- `app/data/users.py` reads users from JSON
- `app/data/matches.py` reads matches from JSON
- `app/data/bets.py` reads bets from JSON

**Expected outcome:** all tabs show the JSON-backed data, not hardcoded fixtures.

### Step 4 — Make “Save bets” persist to JSON in DEMO_MODE
Update `app/data/bets.py: upsert_bets_for_user()` demo path:
- Load bets.json
- For each submitted bet with both scores:
  - upsert by `(username, match_id)`
  - set `home_bet`, `away_bet`, `updated_at`
  - set `status` (likely `"pending"` by default if match not finished)
  - keep `points` null unless you want a simple demo scoring rule (optional)
- Save back to bets.json

**Expected outcome:** after clicking “💾 Zapisz wszystkie zakłady”, refresh/rerun keeps the bets.

### Step 5 — Final QA (deep verification)
- Run:
  - `DEMO_MODE=1 streamlit run streamlit_app.py`
- Verify:
  - login works for 5 users
  - “Złóż zakłady” shows a mix of bet/unbet future matches
  - after save, bets persist (reload page / restart Streamlit)
  - “Mój raport”, “Tabela”, “Centrum - Na żywo” render using JSON data with no Supabase calls
