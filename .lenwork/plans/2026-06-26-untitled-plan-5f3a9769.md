Got it — we’re aligned.

For **your scoring needs today**, the only “scoreline” we must reliably derive is:

> **final score before penalties** = score at the end of the match (after ET if played), but **excluding penalties**.

Given football-data’s “weird” representation, the simplest reliable derivation is:

- If penalties exist (or `duration == PENALTY_SHOOTOUT`):
  - **pre-pen score** = `fullTime - penalties`
- Else:
  - **pre-pen score** = `fullTime` (for REGULAR and EXTRA_TIME)

So yes: **`fullTime - penalties` is exactly what you need**, and it does *not* require RT/ET breakdown.

### What we’ll do in implementation
1) Keep storing `pens_home/pens_away`.
2) Change how we store `flt_home/flt_away` so it represents **pre-penalties final score**:
   - if `pens_*` present: `flt = fullTime - penalties`
   - else: `flt = fullTime`
3) Optionally also fetch/store `regularTime` (and/or keep `extraTime`) for future analysis, but **scoring logic won’t depend on it**.

### Why still consider fetching `regularTime`?
Not because we need it for correctness now, but because:
- it’s useful for later analysis/UX,
- it can help sanity-check bad API edge cases,
- it can support additional UI display (“po 90’ było…”) without re-fetching.

Next step in the scoring+DIP workplan will explicitly encode this mapping and update `transform_match()` accordingly, plus update the scorer to use the corrected `flt_*` and `pens_*`.
